## Roadmap

Infineon **AURIX TC275** 보드로 진행한 임베디드 MCU 과정의 순서다.

1. **GPIO** : 회로도와 데이터시트를 보고 레지스터로 LED, 스위치 제어
2. **인터럽트** : 외부 인터럽트(ERU)로 버튼 입력 처리
3. **타이머와 스케줄링** : STM 타이머 인터럽트, 주기 태스크 → [Timer Interrupt](/2025-02-13-임베디드MCU-Timer-Interrupt/)
4. **통신 / 아날로그 I/O** : SPI, ADC, PWM → [SPI와 7-Segment](/2025-02-14-임베디드MCU/)

### 개발 환경

- **AURIX Development Studio (ADS)** : Infineon이 제공하는 Eclipse 기반 무료 IDE, TASKING 컴파일러 포함
- **iLLD (Infineon Low Level Driver)** : `IfxPort_setPinHigh()` 같은 저수준 드라이버 라이브러리. 이번 과정에서는 원리를 익히기 위해 iLLD 대신 **레지스터를 직접** 다뤘다.
- 디버깅은 보드에 내장된 디버거(DAP)로 브레이크포인트, 레지스터/메모리 확인

### GPIO 인터페이스

- 입력 모드 (Input Mode) : 버튼, 센서 신호를 읽을 때 사용 (풀업/풀다운 선택)
- 출력 모드 (Output Mode) : LED, 모터 드라이버 등 제어 (Push-pull/Open-drain 선택)
- 대체 기능 (Alternate Function) : 같은 핀을 PWM, ADC, UART, SPI 등 주변장치에 연결

## 임베디드 소프트웨어 개발 기초

컴퓨터 시스템의 HW 구조는 CPU, 메모리, 입출력 장치가 버스로 연결된 형태다.
프로그램 카운터(PC)가 가리키는 메모리 위치에서 명령어를 읽어(Fetch), 해석하고(Decode), 실행(Execute)한 뒤 다음 명령으로 넘어간다. 하드웨어 제어도 결국 **특정 주소(레지스터)에 값을 쓰는 명령**이다. ([MCU 메모리 구조](/2025-02-18-메모리구조/))

## 요건 알아야 된다

- 논리회로 : 비트 연산, 레지스터의 의미
- 회로이론 : 풀업/풀다운, 전류 제한 저항
- 컴퓨터구조 : 메모리 맵, 인터럽트, 파이프라인
- 운영체제 : 스케줄링, 동기화
- C 프로그래밍 : 포인터, 비트 연산, `volatile`

## GPIO 개발

1. 회로 파악 : 회로도에서 LED/스위치가 어느 핀에 연결되어 있는지 확인
2. 핀/레지스터 설정 파악 : 데이터시트(User Manual)에서 해당 포트의 레지스터 확인
3. 코드 구현

순서로 진행된다.

### 포트와 핀과 Datasheet

포트 → 핀
포트로 나누어져 있고 핀으로 세분화된다. 예를 들어 `P10.1`은 10번 포트의 1번 핀이다.

TC275에서 GPIO에 쓰는 주요 레지스터는 다음과 같다.

| 레지스터 | 역할 |
| --- | --- |
| `Pn_IOCR0~12` | 핀 모드 설정. 핀마다 5비트(PCx) 필드 (입력/출력, 풀업/풀다운, Push-pull/Open-drain) |
| `Pn_OUT` | 출력 값 쓰기 (포트 전체를 한 번에) |
| `Pn_OMR` | 출력 수정. 하위 16비트(PS)는 Set, 상위 16비트(PCL)는 Clear. **둘 다 1이면 Toggle** |
| `Pn_IN` | 입력 값 읽기 |

- `IOCR0`에는 핀 0~3의 설정이 들어 있고, 핀 n의 필드 시작 비트는 `3 + 8n`이다. 그래서 핀 1은 11번 비트, 핀 2는 19번 비트(`PCn_1_IDX 11`, `PCn_2_IDX 19`)다.
- 대표 설정 값 : `0x10` = 범용 출력(Push-pull), `0x02` = 입력(풀업)

## 스위치

### Push-pull

- 출력단에 트랜지스터 두 개(위: VCC 쪽, 아래: GND 쪽)가 있어 **High와 Low를 모두 직접 구동**한다.
- 빠르고 구동력이 좋아 LED 같은 일반 출력에 쓴다.

### Open drain

- 아래쪽(GND 쪽) 트랜지스터만 있어서 **Low로 끌어내리거나, 연결을 끊는(High-Z) 것**만 가능하다.
- High를 만들려면 외부 **풀업 저항**이 필요하다.
- 여러 장치가 한 선을 공유해도 충돌이 없다(누군가 Low로 당기면 Low). 그래서 **I2C 버스**, 인터럽트 라인 공유, 다른 전압 레벨 장치 연결에 쓴다.

버튼 입력은 내부 풀업을 켠 입력으로 설정하면, 안 누를 때 1, 누를 때 0이 된다.

IOCR을 사용한다.

레지스터에 값을 쓰는 대입문 한 줄도 Load-Modify-Store로 나뉘어 일반적으로 5~10 clock 정도 사용한다. ([코드 프로파일링](/2025-02-18-CodeProfiling/)에서 직접 확인)

아래는 **버튼을 누를 때마다 한 번만 동작**(에지 검출)하게 만드는 여러 방법을 비교한 것이다. 버튼을 누르고 있는 동안 루프가 수만 번 돌기 때문에, 상태 변화를 감지하지 않으면 한 번 누른 것이 여러 번 처리된다.


```c
    P10_OMR.U = 0x20004;
    while(1)
    { // pull up button이기 때문에 땠을 때 1이 된다.


        // 방법 1
        ppushed = pushed;
        if((P02_IN.U & (0x1 << P1_IDX))==0){ // 눌렀을 때, P02_IN.U = 0 이된다.
            pushed = 1;
        }else pushed = 0;
        if((!pushed == ppushed) && pushed){
            P10_OMR.U = 0x60006;
        }
        P10_OMR.U = 0x00000;
        // ---------------------


        // 방법 2
        if(P02_IN.U & (0x1 << P1_IDX)){
            while(1){
                P10_OMR.U = 0x60006;
                if ((P02_IN.U & (0x1 << P1_IDX))==0) {
                    break;
                }
            }
        }
        P10_OMR.U = 0x00000;
        // ---------------------
        /*
        Deadlock(데드락)이란, 일련의 프로세스들이 서로가 가진 자원을 기다리며 block 되어 더 이상 진행이 될 수 없는 상태를 말한다.
        */

        // 교수님 풀이
        // 1st solution
        curSW = P02_IN.U & (0x1<<P1_IDX);
        if(preSW && !curSW){
            P10_OMR.U=0x20002;
        }
        preSW = curSW;

        //2nd solution
        if (!(P02_IN.U & (0x1<<P1_IDX))){
            P10_OMR.U=0x20002;
            while(!(P02_IN.U & (0x1<<P1_IDX))) ;
        }

        //3rd solution
        if (!(P02_IN.U & (0x1<<P1_IDX))){
            cnt++;
        }
        if((P02_IN.U & (0x1<<P1_IDX))){
            if (cnt>1000){
                P10_OMR.U=0x20002;
            }
            cnt = 0;
        }

        //delay
        if (!(P02_IN.U & (0x1<<P1_IDX))){
            P10_OMR.U=0x20002;
            delay(1000);
        }
    }
```

## 인터럽트

### ISR 호출 및 실행
ISR 호출을 위한 3조건
1. 전역적 인터럽트 활성 비트 세트
2. 인터럽트 별 인터럽트 활성화 비트 셋
3. 인터럽트 발생 조건 충족

### 인터럽트 처리 순서
2번 인터럽트가 발생했다고 가정하면 일반적인 MCU는 다음 순서로 처리한다.

1. 현재 실행 중인 명령을 마친다.
2. 현재 상태(PC, 상태 레지스터 등 Context)를 스택/저장 영역에 **자동으로 저장**한다.
3. Program Counter를 인터럽트 벡터 테이블의 2번 위치로 이동한다.
4. 벡터 테이블에 등록된 해당 ISR을 실행한다.
5. ISR이 끝나면(return from interrupt) 저장했던 Context를 복원하고 원래 코드로 돌아간다.

TC275(TriCore)는 조금 다르다.

- 각 인터럽트 소스는 **SRN(Service Request Node)** 에 우선순위 번호(SRPN)를 설정한다.
- 인터럽트 라우터가 대기 중인 요청 중 가장 높은 우선순위를 골라 CPU에 전달하고, CPU는 현재 우선순위(CCPN)보다 높을 때만 받아들인다.
- 벡터 테이블의 위치는 소스 번호가 아니라 **우선순위 번호**로 결정된다. `IFX_INTERRUPT(ISR0, 0, 0x10)`의 마지막 인자가 그 우선순위다.

``` c
#include "Ifx_Types.h"
#include "IfxCpu.h"
#include "IfxScuWdt.h"

IfxCpu_syncEvent g_cpuSyncEvent = 0;

#define PCn_1_IDX 11 // D12
#define PCn_2_IDX 19 // D13
#define PCn_3_IDX 27 // D10

#define P1_IDX 1 // D12
#define P2_IDX 2 // D13
#define P3_IDX 3 // D10

#define PSn_1_IDX 1
#define PSn_2_IDX 2
#define PCLn_1_IDX 17
#define PCLn_2_IDX 18

#define EXIS0_IDX 4     // external input selection, 0: input 20 1: input 21...
#define FEN0_IDX 8      // falling edge enable, 0: not used 1: falling edge
#define EIEN0_IDX 11    // external input enable, 0: disabled 1: enabled
#define INP0_IDX 12     // input node pointer, 000: trigger output OGU0
#define IGP0_IDX 14     // interrupt gating pattern, 01: IOUT is activated in a trigger event. pattern is not considered.
#define SRE_IDX 10
#define TOS_IDX 11

#define REN0_IDX 9      // rising edge enable, 0: not used 1: rising edge

void initGPIO(void);
void initERU(void);

int state = 0;

IFX_INTERRUPT(ISR0, 0, 0x10); // (isr, vectabNum, prio)
void ISR0(void) {
    P10_OUT.U = 0x1 << P1_IDX;
}

int core0_main(void)
{
    IfxCpu_enableInterrupts();
    
    /* !!WATCHDOG0 AND SAFETY WATCHDOG ARE DISABLED HERE!!
     * Enable the watchdogs and service them periodically if it is required
     */
    IfxScuWdt_disableCpuWatchdog(IfxScuWdt_getCpuWatchdogPassword());
    IfxScuWdt_disableSafetyWatchdog(IfxScuWdt_getSafetyWatchdogPassword());

    /* Wait for CPU sync event */
    IfxCpu_emitEvent(&g_cpuSyncEvent);
    IfxCpu_waitEvent(&g_cpuSyncEvent, 1);

    initGPIO();
    initERU();

    while(1)
    {
    }

    return 1;
}

void initGPIO(void) {

    P10_IOCR0.U &= ~(0x1f << PCn_2_IDX);
    P10_IOCR0.U &= ~(0x1f << PCn_1_IDX);
    P10_IOCR0.U |= 0x10 << PCn_2_IDX;
    P10_IOCR0.U |= 0x10 << PCn_1_IDX;

    P02_IOCR0.U &= ~(0x1f << PCn_1_IDX);
    P02_IOCR0.U |= 0x02 << PCn_1_IDX;
}

void initERU(void) {
    // P2.1을 인터럽트로 사용하도록 설정
    // set EICR - system control unit (SCU)의
    SCU_EICR1.U &= ~(0x6 << EXIS0_IDX);
    SCU_EICR1.U |= 0x1 << EXIS0_IDX; // input select

    SCU_EICR1.U |= 0x1 << REN0_IDX;  // trigger edge
    SCU_EICR1.U |= 0x1 << EIEN0_IDX; // enable

    SCU_EICR1.U &= ~(0x7 << INP0_IDX);

    // set IGCR -
    SCU_IGCR0.U &= ~(0x3 << IGP0_IDX);
    SCU_IGCR0.U |= 0x1 << IGP0_IDX;

    // set SCUERU
    SRC_SCU_SCU_ERU0.U &= ~0xFF; // Service request is on lowest priority
    SRC_SCU_SCU_ERU0.U |= 0x10;  // ?

    SRC_SCU_SCU_ERU0.U |= 0x1 << SRE_IDX; // Service Request Enable
    SRC_SCU_SCU_ERU0.U &= ~(0x3 << TOS_IDX); // CPU0 is initiated

}


```

    SCU_EICR1.U |= 0x1 << EXIS0_IDX;
