## 리눅스는 모든 장치를 **파일**로 생각한다.

`/dev/ttyUSB0`(시리얼), `/dev/sda`(디스크), `/dev/gpiochip0`(GPIO)처럼 장치가 파일로 보이고, 응용 프로그램은 `open()`, `read()`, `write()`, `ioctl()` 같은 파일 함수로 장치를 다룬다. 그 파일 함수 호출을 실제 하드웨어 동작으로 바꿔 주는 것이 **디바이스 드라이버**다.

## 디바이스 드라이버
- 장치를 바꿀때 마다 펌웨어를 새로 갈아야하는 문제가 생기기 때문에 추상적으로 구현해 놓고 드라이버로서 내부 소프트웨어를 작성한다.

``` c
module_init(hi_init); // 이거를 디바이스 드라이버가 정의하고 채운다.
module_exit(hi_exit); // 이거는 리눅스 내부적으로 구현이 되어있다.
```
- `module_init()` / `module_exit()`는 드라이버가 정의한 초기화/종료 함수(`hi_init`, `hi_exit`)를 커널에 **등록**하는 매크로다. 모듈을 올릴 때(`insmod`) init 함수가, 내릴 때(`rmmod`) exit 함수가 호출된다.
- 드라이버를 커널에 처음부터 넣지 않고 **모듈(.ko)** 로 만들면, 재부팅 없이 올리고 내릴 수 있다.

```bash
sudo insmod hi.ko     # 모듈 적재 → hi_init 실행
dmesg | tail          # printk 출력 확인
sudo rmmod hi         # 모듈 제거 → hi_exit 실행
```

### 종류

리눅스에는 Device Driver가 크게 3가지 존재한다.

| 종류 | 데이터 단위 | 예시 |
| --- | --- | --- |
| **Character Device Driver** | 바이트 스트림, 순차 접근 | 시리얼, 키보드, GPIO, 센서 |
| **Block Device Driver** | 블록 단위, 임의 접근 (버퍼 캐시 사용) | HDD, SSD, SD카드 |
| **Network Device Driver** | 패킷 단위, 파일이 아닌 소켓 인터페이스 | 이더넷, Wi-Fi |

## Character Device Driver 개발

가장 기본이 되는 Character Device Driver의 구조는 다음과 같다.

1. **주 번호(Major) 할당** : `register_chrdev()` 또는 `alloc_chrdev_region()`으로 장치 번호를 받는다.
2. **file_operations 구조체 작성** : 응용 프로그램의 `open/read/write/release` 호출이 연결될 드라이버 함수를 지정한다.
3. **장치 파일 생성** : `mknod` 또는 `class_create/device_create`로 `/dev/장치명`을 만든다.
4. 응용 프로그램은 그 파일을 열어 읽고 쓴다.

```c
static struct file_operations hi_fops = {
    .owner   = THIS_MODULE,
    .open    = hi_open,
    .read    = hi_read,     /* copy_to_user()로 커널 → 사용자 공간 복사 */
    .write   = hi_write,    /* copy_from_user()로 사용자 → 커널 공간 복사 */
    .release = hi_release,
};
```

커널 공간과 사용자 공간은 메모리가 분리되어 있어서, 포인터를 그대로 쓰지 않고 반드시 `copy_to_user()` / `copy_from_user()`로 복사해야 한다.

## Makefile
- 만일 생성해야하는 object 파일이 많다. 그러면 명령어로 모두 작성하기 번거롭다.
- Shell script가 아니라 make문법을 사용하는 이유는 뭘까?
  - **증분빌드(increment build)** 때문이다.
  - 컴파일된 오브젝트 파일은 소스가 바뀌지 않았으면 다시 빌드하지 않기 때문이다. shell script일 경우 모든 경우를 매번 처음부터 다시 컴파일한다.
  - make는 **타깃과 의존 파일의 수정 시간**을 비교해서, 바뀐 소스와 그것에 의존하는 파일만 다시 만든다. 파일이 수백 개인 프로젝트에서 빌드 시간이 크게 줄어든다.

```makefile
CC = gcc
CFLAGS = -Wall -O2
OBJS = main.o uart.o led.o

app: $(OBJS)
	$(CC) -o $@ $^

%.o: %.c
	$(CC) $(CFLAGS) -c $<

clean:
	rm -f $(OBJS) app
```

- `$@` : 타깃 이름, `$^` : 모든 의존 파일, `$<` : 첫 번째 의존 파일
- 커널 모듈은 커널 소스의 빌드 시스템(Kbuild)을 호출하는 Makefile(`obj-m += hi.o`)을 쓴다.


## 내부망을 이용해서 원격 접속

같은 네트워크(공유기 아래)에 있는 보드나 VM에는 SSH로 접속했다.

```bash
sudo apt install openssh-server   # 접속받을 쪽
ip addr                           # 내부 IP 확인 (예: 192.168.0.23)
ssh user@192.168.0.23             # 접속하는 쪽
```

- VirtualBox VM에 접속하려면 네트워크를 **브리지 어댑터**로 바꾸거나, NAT에서 **포트 포워딩**(호스트 2222 → 게스트 22)을 설정해야 한다.

## 외부 IP 원격접속은 포트포워딩이 어려워 불가능하다고 판단함

- 외부에서 접속하려면 공유기에서 외부 포트를 내부 IP로 넘겨주는 포트포워딩이 필요하다.
- 교육장 네트워크는 공유기 설정 권한이 없고, 상위에 NAT가 한 번 더 있을 수 있어서 직접 연결은 어렵다고 판단했다.
- 대안으로는 VPN(Tailscale 등)이나 역방향 SSH 터널을 쓰는 방법이 있다.
