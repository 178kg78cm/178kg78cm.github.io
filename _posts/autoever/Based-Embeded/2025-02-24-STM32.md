## MCU Bring-Up
Firmware를 통해 MCU가 기본적으로 동작하는 것

새 보드를 받으면 보통 다음 순서로 확인한다.

1. 전원과 디버거 연결 (보드가 인식되고 Flash에 쓸 수 있는가)
2. **클럭 설정** (RCC) : 원하는 시스템 클럭으로 동작하는가
3. **GPIO로 LED 토글** : 코드가 실제로 실행되는가 (임베디드의 Hello World)
4. UART 출력 : 디버깅 통로 확보 ([STM32 UART](/2025-02-28-STM32_UART/))
5. 인터럽트, 타이머, 나머지 주변장치


## I/O Access 방법
- **Special Instruction I/O (Port-mapped I/O)**
  - I/O 전용 주소 공간과 전용 명령어(`in`, `out`)로 접근한다. (x86)
- **Memory-mapped I/O**
  - 주변장치 레지스터가 메모리 주소 공간에 배치되어, 일반 Load/Store 명령으로 접근한다. ARM 기반 MCU는 모두 이 방식이다.
  - SPI/I2C/UART 등 통신 주변장치의 데이터 레지스터도 이 방식으로 읽고 쓴다.
- **Direct Memory Access (DMA)**
  - CPU 개입 없이 DMA 컨트롤러가 주변장치 ↔ 메모리 간 데이터를 옮긴다. 대량 데이터(ADC 연속 변환, UART 수신 버퍼)에 쓴다.


## 저항
- PULL UP
- PULL DOWN
Pull up을 더 많이 쓴다. 눌렀을 때 GND에 직접 연결되어 0이 되기 때문에 더 확실하게 구분이 가능하다. 만일 Pull Down일 경우 눌렀을 때 1인데 이 때 voltage의 threshold를 정확하게 분간하기 어려운 경우도 있기 때문
- Open Drain

## Little Endian vs Big Endian

여러 바이트로 된 값을 메모리에 저장하는 **바이트 순서**다. `0x12345678`을 0x2000_0000 주소에 저장하면,

| 주소 | +0 | +1 | +2 | +3 |
| --- | --- | --- | --- | --- |
| Little Endian | `78` | `56` | `34` | `12` |
| Big Endian | `12` | `34` | `56` | `78` |

- **Little Endian** : 낮은 주소에 하위 바이트. ARM Cortex-M(STM32), x86, TriCore 등 대부분의 MCU
- **Big Endian** : 낮은 주소에 상위 바이트. 네트워크 바이트 순서(TCP/IP), 일부 PowerPC MCU
- 통신에서 특히 중요하다. CAN 신호의 **Intel(Little) / Motorola(Big)** 바이트 순서를 잘못 맞추면 값이 엉뚱하게 해석된다.

```c
uint32_t x = 0x12345678;
uint8_t *p = (uint8_t *)&x;
printf("%02X
", p[0]);   /* Little Endian이면 78 */
```

## Polling vs interrupt

| 구분 | Polling | Interrupt |
| --- | --- | --- |
| 방식 | CPU가 반복해서 상태를 확인 | 이벤트가 생기면 하드웨어가 CPU에 알림 |
| 장점 | 단순, 타이밍 예측 쉬움 | CPU가 다른 일을 할 수 있음, 빠른 응답 |
| 단점 | CPU 낭비, 이벤트 놓칠 수 있음 | 공유 데이터 보호 필요, 디버깅 어려움 |
