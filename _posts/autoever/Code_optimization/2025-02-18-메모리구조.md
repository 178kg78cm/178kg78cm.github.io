물리적인 메모리 구조에 적절하게 하드웨어가 매핑되어 있다.
CPU 입장에서는 Flash도, RAM도, 주변장치 레지스터도 모두 **주소 공간의 한 구역**일 뿐이다. 그래서 C 코드에서 포인터로 특정 주소에 값을 쓰면 LED가 켜지는 일이 가능하다(Memory-mapped I/O).

## CPU 구조

MCU 안에서 CPU와 메모리, 주변장치는 버스로 연결된다.

```text
          ┌──────── CPU Core ────────┐
          │ Register File  ALU  PC   │
          │ Local Memory (Scratchpad)│
          └───────────┬──────────────┘
                      │  System Bus (Crossbar)
     ┌────────────────┼──────────────────┐
  Program Flash    Data RAM        Peripheral (SFR)
  (코드, 상수)     (변수, 스택)     (GPIO, Timer, CAN ...)
```

- **PC(Program Counter)** 가 가리키는 주소에서 명령어를 가져와(Fetch) 해석하고(Decode) 실행한다(Execute).
- 변수는 RAM, 코드와 상수(`const`)는 Flash, 하드웨어 제어는 SFR 영역에 있다.
- 어떤 섹션을 어느 주소에 둘지는 **링커 스크립트**(TASKING의 `.lsl`, GCC의 `.ld`)가 정한다. 빌드 결과물인 `.elf`에 이 배치가 그대로 담긴다.

## TC275 분석

실습에 사용한 Infineon **AURIX TC275**의 특징은 다음과 같다.

| 항목 | 내용 |
| --- | --- |
| CPU | TriCore 코어 3개 (멀티코어), 최대 200MHz |
| 안전 | 일부 코어 Lockstep 지원, ISO 26262 ASIL-D 대상 설계 |
| Program Flash | 4MB |
| Data Flash | EEPROM 에뮬레이션용 (설정값 저장) |
| RAM | 코어별 Scratchpad(PSPR/DSPR) + 공유 RAM(LMU) |
| 주변장치 | GTM(타이머), VADC, QSPI, MultiCAN, ASCLIN(UART) 등 |

### TC275 메모리 맵 (요약)

TriCore는 32비트 주소의 **최상위 4비트(Segment)** 로 메모리 영역을 구분한다.

| Segment | 주소 | 영역 |
| --- | --- | --- |
| 0x5 / 0x6 / 0x7 | `0x5000_0000` ~ | CPU2 / CPU1 / CPU0의 DSPR (전역 주소) |
| 0x8 | `0x8000_0000` ~ | Program Flash (**Cached**) |
| 0xA | `0xA000_0000` ~ | Program Flash (**Non-cached**) |
| 0xC | `0xC000_0000` ~ | 현재 코어의 PSPR (로컬 주소) |
| 0xD | `0xD000_0000` ~ | 현재 코어의 DSPR (로컬 주소) |
| 0xF | `0xF000_0000` ~ | 주변장치 레지스터(SFR) |

[코드 프로파일링](/2025-02-18-CodeProfiling/) 글의 디스어셈블리를 다시 보면,

- 코드 주소가 `0x8000_006C`처럼 **0x8 세그먼트**(캐시된 Flash)에서 실행되고
- `movh.a a15, 0xF004` 후 `[a15]-0x4FF0`로 접근하는 주소는 `0xF003_B010`으로, **0xF 세그먼트의 P10_IOCR0 레지스터**다.

메모리 맵을 알면 디스어셈블리만 보고도 "지금 Flash에서 코드를 읽는 중이구나", "포트 레지스터를 건드리는구나"를 알 수 있다.

## 메모리 리매핑 (Re-mapping)

**같은 물리 메모리를 여러 주소로 접근할 수 있게 하는 것**이 리매핑(또는 aliasing)이다.

1. **Cached / Non-cached 접근**
   - 같은 Flash가 `0x8...`(캐시 사용)과 `0xA...`(캐시 미사용) 두 주소로 보인다.
   - 실행 속도가 중요한 코드는 0x8로, 캐시 때문에 최신 값이 아닐 수 있는 데이터(다른 코어와 공유 등)는 0xA로 접근한다.
2. **Local / Global 주소**
   - 각 코어의 Scratchpad RAM은 자기 자신에게는 `0xD000_0000`(로컬)으로, 다른 코어에게는 `0x7000_0000`(CPU0) 같은 전역 주소로 보인다.
   - 그래서 **같은 코드가 어느 코어에서 돌든 0xD 주소로 자기 RAM을 쓸 수 있다.**
3. **부트/벡터 리매핑**
   - 일반적인 MCU에서는 0번지(리셋 벡터 영역)를 Flash, System Memory(부트로더), SRAM 중 무엇으로 볼지 바꿀 수 있다. STM32의 BOOT 핀 설정이 대표적인 예다.

## RISC vs CISC

| 구분 | RISC | CISC |
| --- | --- | --- |
| 명령어 | 단순하고 개수가 적음, 고정 길이 위주 | 복잡하고 개수가 많음, 가변 길이 |
| 1명령 실행 | 대부분 1클럭 (파이프라인에 유리) | 여러 클럭 |
| 메모리 접근 | Load/Store 명령으로만 | 연산 명령이 직접 메모리 접근 |
| 레지스터 | 많음 | 상대적으로 적음 |
| 대표 | ARM, RISC-V, TriCore, AVR | x86 |

- 임베디드 MCU는 대부분 RISC다. 명령어가 단순해야 **파이프라인과 실행 시간을 예측하기 쉽고**, 이는 실시간 시스템에 중요하다.
- TriCore는 RISC 기반에 DSP 연산과 16/32비트 혼합 명령어를 더한 구조다. 위 디스어셈블리에서 `ld.w`(Load) → `insert`(연산) → `st.w`(Store)로 **메모리 연산이 Load/Store로 분리**되는 것이 RISC의 특징을 잘 보여 준다.
- 요즘 x86도 내부적으로는 복잡한 명령을 RISC 형태의 micro-op으로 쪼개 실행하므로, 둘의 경계는 많이 흐려졌다.
