## 동적 할당 : new vs malloc

웬만하면 stack에서 모든 작업을 하되, 동적 할당이 필요하다면 `new`를 사용한다. 생성자 호출과 예외를 던져 주는 작업이 가능하기 때문이다.

| 구분 | `malloc` / `free` | `new` / `delete` |
| --- | --- | --- |
| 종류 | 함수 (C 라이브러리) | 연산자 (C++) |
| 생성자/소멸자 | 호출 안 함 | 호출함 |
| 반환 타입 | `void*` (형변환 필요) | 정확한 타입 |
| 실패 시 | `NULL` 반환 | `std::bad_alloc` 예외 |

`free`를 한다고 해서 메모리가 사라지는 것은 아니다?

- `free`/`delete`는 그 메모리를 **힙 관리자에게 "다시 써도 된다"고 돌려주는 것**이지, 값을 지우거나 OS에 즉시 반납하는 것이 아니다.
- 그래서 해제 후에도 포인터로 접근하면 옛 값이 읽히기도 하는데, 이것이 **Dangling Pointer**다. 언제든 다른 할당에 재사용될 수 있으므로 정의되지 않은 동작이다.
- 해제 후에는 포인터를 `nullptr`로 만드는 습관을 들이고, 가능하면 아래의 스마트 포인터를 쓴다.
- 임베디드에서는 힙 단편화와 실행 시간 예측 문제 때문에 **런타임 동적 할당 자체를 금지**하는 경우가 많다. (MISRA, AUTOSAR C++14)

## uniform 초기화 (중요하다.)

최초 정의할 때, 동시에 초기화하는 방법. C++11 이전에는 타입마다 초기화 문법이 달랐다.

```cpp
int          a1     = 0;            // 기본 데이터형은 = 연산자로 초기화, 괄호가 없다.
struct point b1     = { 0, 0 };     // 구조체는 중괄호
int          c1[3]  = { 11, 22, 33 }; // 배열은 중괄호
rect         d1(1, 2);              // 클래스는 소괄호
```

C++11의 **uniform initialization**은 이것을 모두 중괄호 하나로 통일한다.

```cpp
int   a2{0};
point b2{0, 0};
int   c2[3]{11, 22, 33};
rect  d2{1, 2};

int x{3.14};   // 컴파일 에러 : 축소 변환(narrowing)을 막아 준다
```

## Call by value / address / reference

함수가 호출될 때 매개변수에 인자를 넣는 방식에 따라 call by value, call by address, call by reference로 구분된다.

- call by value : 값에 의한 전달 (복사본을 다룸)
- call by address : 주소에 의한 전달 (포인터)
- call by reference : 참조에 의한 전달 (별칭)

Call by address와 Call by reference의 차이

- 위 둘은 해당 변수에 접근하여 값을 수정할 수 있다는 점은 똑같다.
- address는 매개변수가 포인터 변수로 선언되어, 주소값을 저장하는 별도의 변수가 생긴다. `nullptr`이 들어올 수 있고, 다른 곳을 가리키도록 바꿀 수 있다.
- reference는 매개변수가 참조 변수로 선언되어 **원래 변수의 다른 이름(별칭)** 처럼 동작한다. 반드시 초기화되어야 하고 null이 될 수 없어서 더 안전하다. (내부적으로는 컴파일러가 포인터처럼 구현하는 경우가 많다.)
- 그래서 C++에서는 reference를 사용하는 것이 좋다. 큰 객체를 복사 없이 읽기만 할 때는 `const T&`를 쓴다.

```cpp
#include <iostream>

using namespace std;
void swap(int* a, int* b) { // call by address
    int temp = *a;
    *a = *b;
    *b = temp;
}
void swap(int& a, int& b) { // call by reference
    int temp = a;
    a = b;
    b = temp;
}

int main() {
    int a, b;
    cin >> a >> b;

    cout << a << ' ' << b << '\n';
    swap(&a, &b);
    cout << a << ' ' << b << '\n';
    swap(a, b);
    cout << a << ' ' << b << '\n';
    return 0;
}
```

## define과 inline 차이점

[참고 글](https://velog.io/@mandarin926/%EC%A0%95%EB%A6%AC-3%EC%9D%BC%EC%B0%A8)

- 매크로(define)는 **전처리기**에 의해 단순 치환된다.
- inline은 **컴파일러**의 판단에 의해 처리된다. (인라이닝할지, 그냥 함수로 호출할지)
- inline은 데이터 타입을 정의해야 하므로 타입 검사가 되지만, 매크로(define)는 그렇지 않다.
- 매크로는 `SQUARE(x++)`처럼 인자가 여러 번 평가되는 부작용이 있다. C++에서는 매크로 대신 `inline`, `constexpr`, 템플릿을 쓴다.

## 객체지향

### OOP의 꽃은 다형성(Polymorphism)이다.

같은 인터페이스로 호출해도 실제 객체의 타입에 따라 다른 동작을 하는 것이다.

### OCP(Open Closed Principle) 원칙

개방-폐쇄 원칙(OCP, Open-Closed Principle)은 '소프트웨어 개체(클래스, 모듈, 함수 등)는 확장에 대해 열려 있어야 하고, 수정에 대해서는 닫혀 있어야 한다'는 프로그래밍 원칙이다.

- C에서는 callback function(함수 포인터)을 이용해서 구현한다.
- C++에서는 Interface(순수 가상 함수를 가진 추상 클래스)를 이용해서 구현한다.

### 가상 함수와 순수 가상 함수

```cpp
virtual void draw() {}   // 가상함수 (virtual function)
virtual void draw() = 0; // 순수 가상함수 (pure virtual function)
```

- 가상 함수로 정의하면 하위 클래스에서 재정의를 안 해도 된다. (기본 동작 제공)
- 순수 가상 함수는 구현이 없으므로 **하위 클래스에서 반드시 구현해야 한다.**
- 순수 가상 함수를 하나라도 가진 클래스는 **추상 클래스**가 되어 객체를 만들 수 없다. 추상 클래스는 상속받는 객체가 순수 가상 함수를 반드시 구현하도록 강제한다.

```cpp
class Shape {
public:
    virtual void draw() = 0;
    virtual ~Shape() = default;   // 기반 클래스 소멸자는 virtual로
};

class Circle : public Shape {
public:
    void draw() override { /* 원 그리기 */ }
};

void render(Shape& s) { s.draw(); }   // 새 도형이 추가되어도 render는 수정할 필요 없음 (OCP)
```

상속보다는 인터페이스로 유기적으로 프로그래밍하는 것이 유리하다.

### const 멤버 함수

함수 이름 뒤에 `const`를 붙이면, 그 함수 안에서 멤버 변수 값을 변경하지 않겠다는 약속이다. `const` 객체에서는 `const` 멤버 함수만 호출할 수 있다.

```cpp
int getX() const { return x; }   // x를 바꾸면 컴파일 에러
```

## 스마트 포인터

예외가 발생하는(try-catch) 상황에서도 포인터의 할당을 해제하고 진행한다. 객체가 스코프를 벗어날 때 소멸자에서 자동으로 해제하기 때문이다. (RAII)

- **unique_ptr** : 단일 소유권. 원시 포인터와 다르게 "복사"가 안 된다. 하나만을 가리키기 때문이다. 그러나 `std::move`로 "이동"은 가능하다. 가리키는 대상을 바꿀 수는 있다(`reset`).
- **shared_ptr** : 참조 카운트로 여러 곳이 소유를 공유. 마지막 소유자가 사라질 때 해제된다.
- **weak_ptr** : shared_ptr을 참조만 하고 카운트를 올리지 않는다. 순환 참조를 끊을 때 쓴다.

`make_unique`를 이용해서 포인터를 만들 수 있다. 이 포인터는 자동으로 메모리를 해제하므로 `delete`가 필요 없다.

```cpp
auto p = std::make_unique<Circle>();
auto q = std::move(p);   // 소유권 이동, 이제 p는 nullptr
```

## 스레드 vs 프로세스

| 구분 | 프로세스 | 스레드 |
| --- | --- | --- |
| 정의 | 실행 중인 프로그램 | 프로세스 안의 실행 흐름 |
| 메모리 | 코드/데이터/힙/스택을 **각자 독립적으로** 가짐 | 코드/데이터/힙은 **공유**, 스택만 각자 |
| 생성/전환 비용 | 큼 | 작음 |
| 통신 | IPC 필요 (파이프, 소켓, 공유 메모리) | 공유 메모리로 바로 가능 |
| 안정성 | 한 프로세스가 죽어도 다른 프로세스는 영향 적음 | 한 스레드의 오류가 프로세스 전체를 죽일 수 있음 |

스레드는 메모리를 공유하기 때문에 빠르지만, 같은 데이터를 동시에 건드리면 **경쟁 상태(Race Condition)** 가 생긴다. 그래서 `std::mutex`, `std::atomic` 같은 동기화가 필요하다. 이 문제는 RTOS의 태스크에서도 똑같이 나타난다. ([우선순위 역전 현상](/2025-03-20-우선순위역전현상/))
